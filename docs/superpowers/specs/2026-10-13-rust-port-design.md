# Rust port of the phase 0 analysers: design

Date: 2026-10-13, revised the same day after an adversarial review. Status: for the owner's review. Parent: `2026-10-04-lazymkv-design.md` (the design spec; its decisions D1 to D23 bind this document). Owner decisions taken while brainstorming (2026-10-13): the repository becomes Rust plus the mini PC's PowerShell jobs; the port is one pull request; the committed baselines in the evidence repository are the acceptance tests. The owner first took the recommendation to delete the seven one-off readers; the review showed that five of them serve experiments the phase report lists as open and that the plan's routine still calls them, so this revision ports all fifteen modules (section 2) and records that correction for the owner's confirmation.

## 1. Purpose

Phase 0 measured MakeMKV, mkvmerge and ffmpeg with Python analysers under `scripts/phase0/`. Three of them are the first versions of decision rules the product ships (the audio content rule of spec 8.6, the subtitle text rule of 8.7, the scan-versus-file reconciler of 6.2 step 7), and the tuning harness behind decision D16 only exists in Python. This pull request moves that logic into the `core` crate the design spec names for phase 1, adds a `lazymkv-dev` binary that runs it over recordings, and deletes every Python file and every `python3` call in the repository. When it merges, `cargo test --workspace` on a checkout with the evidence clone proves that the Rust gives the recorded verdicts, and no Python remains.

## 2. Scope

Of the fifteen Python modules under `scripts/phase0/`, all fifteen are ported. Seven carry rule logic into `core`; `proxy_levels.py` and the seven small readers (30 to 300 lines over the robot parser) become eight `lazymkv-dev` commands, because experiments 2, 8, 10, 11 and 12 are still open and the plan's routine steps call them.

## 3. Architecture

### 3.1 Crates and dependencies

`crates/core` (exists: `fingerprint`, `profile`) gains the modules of section 2 plus `lang` (two tables, as the Python has them: `compare_tracks.B_TO_T` for the reconciler's bibliographic-to-terminology mapping, and `audio_similarity.ISO639` with `NO_LANGUAGE = "", -, und, zxx, mul, mis` and TMDb's `xx`) and `recording` (section 3.3). `core` keeps the design spec's rule: no I/O, nothing OS-specific; every function takes parsed inputs or an in-memory tree (section 3.2) and returns values or typed errors. Its `Cargo.toml` adds `serde` (derive), `serde_json` with the `preserve_order` and `float_roundtrip` features, `regex` (the marker patterns), `fancy-regex` (the seven OCR corrections, which use look-behind and look-ahead; `fancy_regex::Regex::replace_all` is one pass over the original text like `re.subn`), and `unicode-normalization` (NFKD plus the canonical combining class for `fold`). `md-5` and `sha1` are already there.

`crates/dev` is new, a workspace member, and builds the binary `lazymkv-dev`. It owns all I/O: building the in-memory tree from a directory, reading files, writing files and snapshots, running `ffprobe` and `ffmpeg` through an injectable runner trait (so the mocked Python tests port as they are), printing, exit codes. Argument parsing is by hand or `clap`; either way the flag spellings of section 3.4 are the Python's. It is the first form of decision D16's developer and tuning mode; phase 2 folds `retune` and `decide` into `lazymkvctl`, and this crate keeps what the engine does not take over.

`crates/capture` and `crates/fake-tools` are unchanged.

### 3.2 The core/dev boundary: the in-memory tree

`core::recording::Tree` is a `BTreeMap<RelPath, Lazy<Bytes>>` of a recording directory, or of the whole evidence directory, with `list(dir)`, `glob(pattern)` and `read(path)`; entries are ordered as Python sorts `Path` objects: component by component, each name by code point, so `all-tracks/...` sorts before `all-tracks-2/...` and `audio-levels-20ms-1-2/...` before `audio-levels-20ms-1-2-3/...` (a test covers both pairs, which exist in the evidence). `crates/dev` builds it from disk, lazily for level series, and hands it to `core`. Every walker in the Python (`find_folders`, `ripped`, the `*/*/audio-levels-20ms-*/audio-proxy.json` scan, `no_audio`, `same_rip`, labels `auto` and `_scan_flags`, `refusal`, `load_title`, `levels_args`) becomes a function over the tree. Folder names `golden/` are skipped by every walker (section 5 reserves the name). A missing file is `Missing(RelPath)`, raised by the tree, never a silent default. Text files are decoded as UTF-8 with an optional byte-order mark, lossily (`from_utf8_lossy`) where the Python read with `errors="replace"`, and each reader splits lines as its Python does: `robot.parse` on `\n` only, with a trailing `\r` stripped per line; the level files (`CRLF`), `manifest.txt`, `refusal`, `exp13_requirements`, `ocr_records`, the hit-rate statuses, `ocr_compare` and `encoding` with the boundaries of Python's `str.splitlines` (`\n`, `\r`, `\r\n`, `\v`, `\f`, `\x1c` to `\x1e`, `\x85`, `\u2028`, `\u2029`), through one shared helper with a test per boundary.

### 3.3 Module contracts

- `core::robot`: `parse(&str) -> Scan`, infallible: a line without `:` or whose fields do not parse is skipped, as `robot.parse` skips it (an optional `skipped: Vec<(line, reason)>` is kept for diagnostics); `PRGC`, `PRGT`, `PRGV`, `TCOUNT` and `HSH` lines are ignored as the Python ignores them (D18 may need `TCOUNT` later; that is a later change). `Scan { messages: Vec<Message>, drives: Vec<Drive>, disc: BTreeMap<u32, String>, titles: BTreeMap<u32, Attrs>, streams: BTreeMap<(u32, u32), Attrs> }` with sparse title numbering kept; `split_fields` matches the Python on every line of every recorded and pinned scan; `duration_seconds(&str) -> Option<u32>`; `None` is `0` in `audio_by_title`, `false` in `exp11`, `null` in `scan.json`, and exit 2 in `reconcile` (where the Python crashed).
- `core::reconcile`: exactly `compare_tracks.py`: `expected_rows(scan, title, selection)` (selection `all` or `eng`), `removed_streams(rip_text)` (MSG:4047 indices mapped through the selection; an index beyond the prediction is reported, not dropped), `file_rows(mkvmerge_json)`, `same_track` (type; language except on video; audio channels when both sides state them; position by position, no exception), `checks` giving the five verdicts `count`, `order`, `video`, `chapters`, `duration` with their numbers (`scan_chapters`, `file_chapters`, `scan_seconds`, `file_seconds`, the symmetric `DURATION_TOLERANCE_S = 2` for every format), the rows, the removed rows, the unknown MSG:4047 indices, `statistics_tags` and `video_tracks`; exit 1 when any verdict is `no`.
- `core::audio::levels`: parsers over text: `parse_manifest(&str)` (first line `# lazymkv audio-levels v2 (experiment 13)`), `parse_levels(&str)` (one dB level per 20 ms frame, floor -100), `parse_streams(&str)` (`streams.json`), `parse_proxy(&str)` (`audio-proxy.json`), and `refusal(tree, folder)` with the Python's messages (a first-form folder, a missing file, a frame length other than 20 ms).
- `core::audio::measures`: `Constants` (the Python's `CONSTANTS`, same defaults, each marked `Int` or `Float`), `analyse(main, cand, dialogue, reverse, &Constants) -> Measures` in the Python's loop order (DC, AG, tenths, SMI with the 64-point precomputed twiddles, LS, ADL, the three lag searches), `reverse_measures`, `swapped`. `SILENT_DB` also decides, outside `analyse`, whether `main-fc.txt` is used (`max(fc) <= SILENT_DB`), as in `results`.
- `core::audio::rule`: `Rule` (the Python's `RULE`), `Verdict` (`duplicate`, `commentary`, `commentary-cross-language`, `reference-unclear`, `ad-pattern`, `note-commentary`, `note-ad`, `keep`, `not-judged`), `verdict`, `commentary_pattern`, `ad_pattern`, `reverse_pattern`, `not_judged`, `cross_language`, the `MEANING` and `VETO_MEANING` texts, and `results(tree, folder, &Rule, &Constants, cache) -> FolderResults` as the folder-level orchestration (duplicates by packet MD5, forward, reverse and peer runs, the veto). `Rule::set(name, value)` and `Constants::set` reproduce `--set`: a rule key matched case-insensitively, a constant upper-cased, a finite number, a whole number for an `Int` key, and the Python's error text listing the valid names.
- `core::audio::reference`: `is_lossless`, `rank`, `placed_first` (8.6 step 3 with guards G1 and G2 as far as ffprobe's facts go), `programme_reference` with the Python's three steps (the original language from `tmdb.json`, else English, else any language when no stream is in a wanted language), `wanted`, both `first_of_language` functions (the rule's over `streams.json` and the dataset's over the title's streams, with their different signatures), `position_veto` (row 0, D21).
- `core::audio::titles`: `segments`, `audio_by_title` (the derived flag 2048 left out, `""` becomes `und`), `dvd_scan` (CINFO 1 contains `DVD`, or a `V_MPEG2` or `S_VOBSUB` stream, and no title attribute 16), `titles_report` with the `<- <lang> x<n>`, `<- wanted x<n>`, `ripped as` and `shares segments with` lines and the DVD line that says no segment check was made.
- `core::audio::report`: the per-folder text report of `audio_similarity.report` line for line (header, `veto:` line, measure lines, reverse and peer lines, the meaning texts, `row:` lines); every folder is checked before anything is printed; a refusal is exit 1.
- `core::audio::labels`: the labels file `lazymkv audio labels v1` and the fitted file `lazymkv audio fitted v1` are handled as `serde_json::Value` with insertion order kept; `problems` and `fitted_problems` run over the value and produce the Python's sentences verbatim; typed views are derived only after validation passes; the edits `set`, `unset`, `title`, `auto` (which also reads `scan.txt` and the rips' `ffprobe-streams.json` through the tree) and `fitted` are functions from a value and its inputs to the new value, sorting tracks by `(label, stream)` and titles by key as `save` does; `KINDS`, `HOW`, `COUNTING_HOW = (listened)`, `OBSERVATION_HOW`, `NOT_COUNTED`, `not_counted_because`.
- `core::audio::dataset`: the harness over the tree: every level folder of every title, the join with labels, the counting against the totals of spec section 17 row 13 read from the spec text handed in (one source for the numbers, as the Python), the FAIL rules, the not-judged exclusions (no language, a language that is neither English nor the original, a folder without `streams.json`), the missing-title list, the report lines, the snapshot. The snapshot format becomes `lazymkv audio dataset snapshot v3`: `code` is `{"rule_version": RULE_VERSION}`; the cache key is `sha1("lazymkv-rule:" + RULE_VERSION + canonical constants JSON (sorted keys, Python number spelling) + per series its little-endian f64 bytes + "|", "|" for none)`; a v2 file is read only for `--compare` and as the previous snapshot of the "Changes since" block, never as a cache seed: the first Rust run computes every measure, so the round trip of section 5 exercises `analyse`. `labels fitted --rule` records `version <n>` after the port. `RULE_VERSION` starts at `1` and is bumped by hand with every change to a measure or threshold; a test runs the harness with the cache off and on and compares, so a missed bump is caught. Exit codes 0, 1 (a FAIL), 2 (an argument or spec problem), 3 (evidence could not be read) are the Python's.
- `core::subtitle::text`: `Rule` (the Python's `RULE`), `fold` (NFKD, canonical combining class, the `FOLD_MAP`), the seven `CORRECTIONS` with their `subn` counts, the marker patterns (`RE_CUE`, `RE_LABEL`, `RE_CHEV`, `RE_NOTE`, `RE_NOTE_LOOSE`, `RE_WRAP`, `RE_WORD`, `RE_WORDLIKE`, confirmed pattern by pattern to need no look-around), `packet_events` (events with durations; packets above `clear_max_bytes`, every packet for a text codec), `measure` (events, readability, language shares, markers CUE/LABEL/M/SO/CS, capital style), `pair_text` (time-free bigram containment), text's `aligned` (rounded to 3 decimals), `split_joined` (its lowercase and uppercase tests as Python's `str.islower` and `str.isupper`: every cased character of one case and at least one cased character), `uc`, `subset_of`, `spec87(tracks) -> roles` (8.7 today, by counts and timing), `decide(tracks, orig_lang, &Rule)` with T0 to T7 as `subtitle_text.decide` implements them (without T4's forced-only-parent and TheDiscDB steps and T5's TheDiscDB rows, which the Python never had), `before_yes(verdict, today)`, the closed-caption set-aside, the report of numbers only. Every measure the Python rounds (`round(x, 3)` and `round(x, 4)`) is rounded by a helper that rounds the exact decimal expansion half to even, with tests at the `.0005` boundaries, because those rounded values meet thresholds.
- `core::subtitle::align`: `events(packets, clear_max_bytes)`, `aligned(a, b, tolerance_s)` (unrounded; a different function from text's), `buckets`, `is_text(codec)`, the `subs/` index.
- `core::recording`: the types for `meta.json`, `files.json`, `rip-summary.json`, `extract-summary.json`, `probe-summary.json`, `mkvmerge.json` (the parts used), `ffprobe-streams.json`, `subs/index.json`, `sub-<n>.packets.json`, `subs-ocr/summary.json`, `sub-<n>.frames.json`, `tmdb.json` (slimmed form: `original_language`, `fetched_at`), `thediscdb-*.json`, `lookup-status.txt`; a rip label is a folder with an `ok` `rip-summary.json` or `extract-summary.json` and an `mkvmerge.json`; the title number comes from that summary and the selection from its profile file name (`eng-only.mmcp.xml` means `eng`, otherwise `all`; the profile is a Windows path, so the name is the part after the last `\\`, never `Path::file_name`); the disc format from `meta.json`.
- Writers (in `crates/dev`): a Python-compatible JSON writer (indent `n`, `": "` and `","` separators, insertion order, `ensure_ascii` as a flag, Python float `repr` spelling, ints and floats kept distinct, `NaN` written as `null`), used for the snapshot (indent 1, ASCII, a trailing newline, written through a `.tmp` file and a rename; its `fitted` list sorted by the Python `repr` of each entry, as `key=str` sorts it), the labels file (indent 2, non-ASCII kept, trailing newline, written through a temporary file and a rename), `streams.json` (indent 1, ASCII); level files with the Python's decimal-string rounding half away from zero and `CRLF` line ends, `manifest.txt` with `LF`.

`--evidence DIR` (default `corpus/owner`, or `LAZYMKV_EVIDENCE`) applies to the commands that resolve a slug (`scan`, `decide`, `plan`, `retune`, `levels-args`, `titles`, `subs` in its slug form, `golden`); the check is the Python's: the directory exists, else exit 3 with the line naming the evidence repository and where to clone it. Exit 3 for that case is a deliberate change from the Python commands that took a path (they exited 1 or 2); the table marks it. `scan`, `titles`, `decide`, `levels-args` and `subs` also accept a recording directory path, so a contributor's own recording, `corpus/scenarios/disc-a-scan` or a pinned log directory works without the clone. `plan` also accepts a recording directory, and takes a pinned log as its bare scan file, never as its directory: such as `corpus/thediscdb/<kind>/<work>/<release>/disc01.txt`, whose fingerprint comes from the log's `HSH` lines and whose TheDiscDB answer comes from `corpus/thediscdb-api/dischash-<fingerprint>.json` when that file exists, else from the `disc01.json` beside the log; a directory is always read as a recording (it needs `scan.txt`). `align`, `levels-from-proxy`, `reconcile`, `labels` and the seven readers take explicit paths and make no evidence check. `--spec` defaults to `docs/superpowers/specs/2026-10-04-lazymkv-design.md` under the repository root, found by walking up from the current directory to the directory whose `Cargo.toml` holds `[workspace]`; when none is found, `--spec` is required.

`decide` prints one JSON document: `reconcile` (the section 3.3 report), `audio` (one entry per level folder of the label: the `results` rows, or `{"skipped": "<reason>"}` with the Python's refusal message when the level series are absent), `subtitles` (`decide`, `spec87` and `before_yes` per stream, or `{"skipped": "<reason>"}` when `--text` is absent or holds no text for the title), `reviews` (the union of the review reasons of the audio verdicts and the subtitle decisions; the reconciler raises none). Its inputs are derived as section 3.3's `recording` states; a label that is not a rip label is reported with its reason and exit 2. One test per recording compares each section with the matching goldens of section 5. Phase 1 appends two sections after `reviews` and leaves the existing six (`slug`, `label`, `reconcile`, `audio`, `subtitles`, `reviews`), and their goldens, byte-identical: `plan` (the `plan` command's document for the recording, with the default settings or those `--settings FILE` names, or `{"skipped": "<reason>"}` when it refuses) and `decision` (the file phase of the label's title: `title_key`; `verify`, the report that maps the file's tracks onto the scan's streams; `facts`, which scan streams each measured fact covered; and `decision`, with the audio and subtitle tracks kept and their order, flags and names, the final path, the three confidences, the review reasons, the notes and the disposition; or `{"skipped": "<reason>"}`). A skipped section never changes the exit code. `reviews` stays the port's union of the audio verdicts' and the subtitle decisions' reasons; the decision's own `reviews` are the product's (design spec 8.8).

Paths in every report are printed relative to the evidence root as `corpus/owner/<slug>/...` whatever `--evidence` says, and the snapshot's `corpus` field is that literal; the lines that carry a decision (the To-label list, the kind-against-verdict table, the experiment 13 block, FAIL, kept and note lines, RESULT, `verdict:` and `row:` lines) are the Python's byte for byte; lines that name a command or a code hash are rewritten and listed here: the To-label hint (`python3 scripts/phase0/audio_labels.py set ...` becomes `lazymkv-dev labels set ...`), the FAIL line that names `audio_dataset.py args` (becomes `lazymkv-dev levels-args`), the note that `proxy_levels.py writes streams.json` (becomes `lazymkv-dev levels-from-proxy`), `rule: audio_similarity.py <sha>` (becomes `rule: version <n>`), and the `Changes since the previous snapshot (<created>, code <sha>)` line (prints `rule version <n>` for a v3 snapshot and the sha for a v2 one). The golden `retune-report.txt` of section 5 is the Python's report with its paths normalised and those five lines mapped, and `golden check` compares every other line byte for byte.

## 4. Exactness

The port reproduces the Python of commit `75fa76a`'s tree (the review fixes of 2026-10-13 included: T2 over a snapshot, the T6 guards, unjudged tracks, the veto without `streams.json`, DVD segment numbers), written by Python 3.9.6 on the Mac:

- Verdicts, markers, classes, roles, counts, orders, review reasons, exit codes and the decision-carrying report lines of section 3.4 are identical.
- Floating-point measures agree within 1e-9 absolute, SMI within 1e-6 (its spectrum sums 64 complex products). The Rust computes in `f64` in the Python's loop order; Python 3.9's `sum` adds left to right, and so does the Rust; `ocr_compare` uses `statistics.mean`, which is exact, and the Rust mean sums exactly (integer-scaled or `Fraction`-like) before dividing.
- Files the Python writes deterministically are byte-identical when written by the Rust from the same inputs: `manifest.txt`, level files, `streams.json`, a labels file after an edit, and a second run's snapshot apart from `created`. The first Rust snapshot differs from the committed v2 baseline in `created`, `code`, every `tracks[].key`, every peer `key` and every `measures_cache` key (the key formula changed), and in nothing else once floats are compared within the tolerance; the comparison is structural (parsed JSON, `NaN` as `null`), and that structural equality is the acceptance.
- `proxy.txt` of a rebuilt level folder is written as `levels rebuilt from <path as given>`, not resolved as the Python resolves it (whose absolute path carries the Mac's user name); it is left out of the goldens and the difference is declared here.

## 5. Acceptance: goldens and ported tests

**Goldens.** `lazymkv-dev golden write` has a Python twin, `write_goldens.py`, which lives in the evidence repository at `corpus/owner/golden/write_goldens.py` beside the files it wrote (its provenance does not depend on how the pull request is merged) and never in this repository. Run on the Mac with the evidence clone, the level series present (the ignored side files under `audio-levels-*`), and the OCR text fetched for every title read (`tuning-fetch.ps1 -Text` per title, then deleted), it writes into `corpus/owner/<slug>/golden/` of the evidence repository:

- `scan.json`: `titles`, `streams` and `disc` of `robot.parse` and `duration_seconds` per title (no `drives`, no `messages`);
- `titles.txt`: the `titles` report;
- `<label>/reconcile.json`: the full section 3.3 reconcile report for every rip label (selection from the profile name, title from the summary);

## 7. Risks

- **Regex semantics.** The seven corrections use look-around: `fancy-regex` runs them; a differential test per pattern (the Python's cases plus every distinct line shape in the recorded OCR text, generated once and committed as a public fixture of synthetic lines) pins `replace_all` against `subn`, counts included. The marker patterns run on `regex`.
- **Unicode tables.** `fold` uses Python 3.9's Unicode 13 tables; `unicode-normalization`'s may be newer. The goldens pin the Mac's Python; a difference on a character the recorded text contains is a finding, not a tolerance.
- **Float order and rounding.** The measures use explicit loops in the Python's order; the 1e-9 bound catches a slip; the half-even decimal helper covers every `round()` that meets a threshold.
- **The spec as data.** `retune` reads row 13's totals from the design spec, so an edit of that row changes the harness; the golden check pins the numbers read.
- **Evidence drift.** A new recording pulled before the port lands changes nothing here: goldens are per recording and the harness ignores unlabelled tracks for its FAIL rules.
- **ffmpeg.** `levels-from-proxy`'s real test needs the recorded ffmpeg version on PATH and a fetched proxy; it skips with a message otherwise, and the mocked tests always run.
- **Size.** About 7,000 lines of Rust and 4,000 of tests in one pull request; the per-module commits, the mapping table and `golden check` are the reviewer's means.
